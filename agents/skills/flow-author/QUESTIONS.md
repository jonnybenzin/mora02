# Question catalogue — authoring a flow

Seven questions, in the order that builds a flow: what comes out, what goes
in, what happens in between, where the person wants to look, where the result
goes, what changes per run, and the name. Ask them one at a time, in your own
words; skip what an earlier answer already settled.

The first two get no offers. From the third on, offer two or three shapes an
answer could take - derived from their answers, never generic - and always the
honest empty one.

---

## 1. What should exist at the end

What is the thing that should be there when the flow has run? One picture, a
short clip, a song, a piece of text, a post that is live, a file in a folder?

*No offers here. Push back on a wish that names no artefact: "something for
the shop" is a purpose, "a nine-second clip with music" is an artefact.*

## 2. What the person brings

What is there at the start - what does the machine get handed? A subject in
words, a text, pictures they upload, the latest thing another tool made, a row
in a table, nothing at all?

*No offers here either. This decides the first step. A flow that starts from
files needs them somewhere the machine reads; say where that is when you know.*

## 3. The way in between

How does the start become the end - what has to happen in the middle? Ask this
only if it is not already obvious from 1 and 2, and offer the two or three
routes the vocabulary allows.

*Offers come from `flow_ops`, not from memory: "a picture first and then a clip
from it", "the text straight into speech", "the latest image, upscaled and
sent". Name the shape, not the op.*

## 4. Where they want to look

Before which step do they want to see what has been made so far and decide
whether to go on? Say plainly which steps cost minutes or money, and which
send something out of the house.

*Offer: after the first picture, right before anything is published, at every
expensive step, or nowhere. "Nowhere" is a real answer for a cheap flow and a
wrong one for a flow that publishes; say so if it is.*

## 5. Where the result goes

What happens to the finished thing? It stays in the library to look at, it is
sent to their phone, it goes out by mail, it is published?

*Offer the ways the vocabulary has. Publishing is a decision, not a delivery -
if they say "publish", ask whether a pause before it is wanted (it is).*

## 6. What varies per run

Which of the values change from run to run, and which are fixed? The subject,
the text, a length, a style?

*Offer: "the subject changes, the rest stays", "everything fixed - one flow,
one result", "I don't know yet". What varies becomes an argument the person
gives when they run the flow.*

## 7. The name

Propose a name from the answers - lowercase words joined with dashes - and ask
whether it fits. Check with `flows_list` that it is not taken; if it is, say so
and propose another.
